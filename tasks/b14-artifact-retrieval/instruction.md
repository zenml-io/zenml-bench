The project in `/app/daily_report` produces a daily sales summary with the ZenML pipeline `daily_report` (`python run.py --date YYYY-MM-DD`, run from `/app/daily_report`). Its `summarise` step stores each day's summary as an artifact: per-region `count`, `total` and `mean`, plus the day's `rows` and `total`. The store holds the last couple of weeks of runs: the morning cron runs (tagged `scheduled`), a few started by hand, and a backfill of some late-August days that finance asked for (those runs are tagged `backfill`). Some runs failed.

Finance now wants to know the top region for the busiest backfilled day. Find the **completed** `backfill` run that processed the largest total amount, and write a new ZenML pipeline `region_report` with exactly one step. That step takes that run's stored summary artifact as its input (the artifact version ZenML recorded for that run, not a re-read of the CSV and not a copy of the numbers) and writes `reports/region_top.json` with two keys: `region`, the region with the largest total in that summary, and `total`, that region's total exactly as it appears in the summary. Run the pipeline so that a completed `region_report` run exists whose input is that artifact version. The entrypoint is `python region_report.py`, run from `/app/daily_report`: with no arguments it picks that summary itself and runs the pipeline; with one argument, an artifact version id, it runs the pipeline on that summary artifact version instead (ops will use this to re-check other days), and the report then describes that summary.

Rules: do not run, modify or delete the existing `daily_report` runs; do not edit anything under `data/`; leave no pipelines other than `daily_report` and `region_report` registered in ZenML when you are done. ZenML documentation is available offline at `/opt/zenml-docs/llms-full.txt`.
