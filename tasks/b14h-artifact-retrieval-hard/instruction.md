The project in `/app/daily_report` produces a daily sales summary with the ZenML pipeline `daily_report` (`python run.py --date YYYY-MM-DD`, run from `/app/daily_report`). Its `summarise` step stores each day's summary as an artifact: per-region `count`, `total` and `mean`, plus the day's `rows` and `total`. The store holds the last few weeks of runs: the morning cron runs (tagged `scheduled`), a few started by hand, and a backfill of some late-August days that finance asked for (those runs are tagged `backfill`). After the first pass, finance sent corrected exports for some of those days and they were processed again under the same date; where a day was processed more than once, the most recent processing that completed is the one that counts for that day, and an earlier one is superseded. Some runs failed.

Finance now wants the top region for the busiest backfilled day: the day whose summary, as it counts under the rule above, has the largest total. Write a new ZenML pipeline `region_report` with exactly one step. That step takes that day's stored summary artifact as its input (the artifact version ZenML recorded for the run that counts, not a re-read of the CSV and not a copy of the numbers) and writes `reports/region_top.json` with four keys: `region`, the region with the largest total in that summary; `total`, that region's total exactly as it appears in the summary; `artifact_name` and `artifact_version`, the name and version number under which ZenML stores that summary artifact, so finance can cite it. Run the pipeline so that a completed `region_report` run exists whose input is that artifact version.

Rules: do not run, modify or delete the existing `daily_report` runs; do not edit anything under `data/`; leave no pipelines other than `daily_report` and `region_report` registered in ZenML when you are done. ZenML documentation is available offline at `/opt/zenml-docs/llms-full.txt`.
